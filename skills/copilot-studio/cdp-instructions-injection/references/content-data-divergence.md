# Content vs Data Field Divergence (Jun 22, 2026)

## The Problem

Copilot Studio topics have two YAML fields in Dataverse:
- `data` — the source/authoring YAML (what you edit)
- `content` — the compiled/processed YAML (what the runtime uses)

These can diverge. A topic can have correct `data` but stale `content`.

## Evidence (Jun 22, 2026)

### SLP Agent (6 topics)
All 6 topics with Question nodes had:
- `data`: correct (no Question node, uses `System.Activity.Text`)
- `content`: stale (still has Question node, asks "please paste the note")
- `content` length >> `data` length (e.g., 4131c vs 1950c)

### QM V2 Agent (2 topics)
DoR Summary and Resident Outlier Analysis:
- `data`: correct (no Question node)
- `content`: stale (still has Question node)
- `content` length >> `data` length (e.g., 3823c vs 2033c)

## API Behavior

### PATCH data — WORKS
```
PATCH /botcomponents({id})
{ "data": "<yaml-string>" }
→ 204 OK
```

### PATCH content — FAILS
```
PATCH /botcomponents({id})
{ "content": "<yaml-string>" }
→ 400 "Unexpected character encountered while parsing value: k"
```

Even patching content with the EXACT same value read via GET fails. The platform has a server-side plugin that blocks ALL writes to content.

### Publish — does NOT sync
`pac copilot publish` succeeds but content remains stale. The publish process does not regenerate content from data.

## Resolution

The only way to update content is through the Copilot Studio UI:
1. Open topic in Copilot Studio
2. More → Open code editor
3. Select All → Paste fixed YAML → Save
4. Publish

## Detection Script

```javascript
const topics = data.value || [];
for (const t of topics) {
  const dLen = (t.data || '').length;
  const cLen = (t.content || '').length;
  const stale = t.data !== t.content;
  if (stale) {
    console.log(`${t.name}: data=${dLen}c content=${cLen}c STALE`);
    const dHasQ = (t.data || '').includes('kind: Question');
    const cHasQ = (t.content || '').includes('kind: Question');
    if (cHasQ && !dHasQ) console.log(`  content has Question but data doesn't`);
  }
}
```

## Why This Happens

The content field is generated by the platform's internal compilation process. When data is updated via API, the platform doesn't automatically recompile content. The compilation only happens through the UI's save/publish flow.

The data field is what the Copilot Studio UI reads for display and routing. The content field is what the agent runtime uses for execution. This split causes the confusion: fixing data makes the topic look correct in the UI, but the live agent still uses the stale content.
