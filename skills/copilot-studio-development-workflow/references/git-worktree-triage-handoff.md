# Git Worktree Triage From Handoff

When taking over a large dirty Copilot Studio monorepo from another tool (Codex, Claude Code, etc.), use this methodology to safely triage before committing.

## Handoff Receipt Checklist

1. **Read the handoff/project context files** — `AGENTS.md`, `CLAUDE.md`, any `.kiro/steering/` files
2. **Check what tool did the handoff** — different tools leave different traces (Codex work dirs, Claude Code scratch files)
3. **Identify the active repo and branch** — not all work dirs are git repos
4. **Run baseline git state commands**:
   ```
   git status --short --branch
   git diff --stat
   git diff --name-status
   git log --oneline --decorate -n 12
   git ls-files --others --exclude-standard
   ```

## Triage By Agent/Folder

Group every dirty file by its agent folder or functional category:

| Category | What goes here |
|----------|---------------|
| Steering & config | AGENTS.md, CLAUDE.md, .kiro/**, .agent/**, .cursorrules |
| Agent topics | `*/topics/*.mcs.yml`, `*/src/Topics/*.mcs.yml` |
| Agent metadata | `*/agent.mcs.yml`, `*/settings.mcs.yml` |
| GPT instructions | `*/gpt/*.txt` or `componenttype 15` dumps |
| Helper scripts | `fix_*.py`, `*.cjs`, `*.ps1` at repo root |
| Backup folders | any folder with `backup` or `archive` in name |
| Generated artifacts | `*_distributed_*`, `*_final12_*`, consolidated/all_topics files |

## Line Ending Detection (CRLF vs LF Noise)

The most common false signal in Copilot Studio repos is line-ending normalization from `pac copilot pull` or `manage-agent.bundle.js clone`. These tools re-export YAML with different line endings.

**Detection pattern in `git diff` output:**

- Old content ending with `\r\r` (double carriage return) → file was stored with doubled CR characters
- New content using `\n` (single LF) → tool normalized to Unix line endings
- No actual YAML structure changed → this is noise, not a real edit

**Detection command:**
```bash
git diff -- <file> | grep '^[-+]' | grep -v '^[-+][-+][-+]' | head -20
```

If the only difference is removal of `\r` characters and YAML key reorganization (added blank lines between every node), it's a re-export normalization, not a content change.

**Genuine content changes to look for:**
- Added/removed `SendActivity`, `EndDialog`, `ConditionGroup`, `Question` nodes
- Changed `userInput:` from `=Topic.Variable` to `=System.Activity.Text`
- Added/removed comment header blocks (e.g., "Microsoft Learn Platinum Standard")
- Changed discipline identifiers (`ST`→`SLP`, `"ST"`→`"SLP"`)
- Modified `additionalInstructions`, `modelDescription`, or `description` fields
- Added routing conditions (new `cond_*` blocks with `BeginDialog`)
- Changed `gptCapabilities` (`webBrowsing: true`→`false`)
- Changed `instructions:` content in `agent.mcs.yml`

## Commit Grouping Strategy

Organize commits by logical scope, not by timing:

1. **Steering + Config** — AGENTS.md, CLAUDE.md, .kiro, .agent (project-level steering)
2. **Per-Agent Fixes** — one commit per agent with real content changes (TheraDoc, SNF Dashboard, etc.)
3. **Line Ending Normalization** — ONLY commit this separately, never mix with content changes

Avoid: "misc changes" commits, mixing agent fixes in one blob, committing line-ending noise alongside content changes.

## What NOT To Commit (Untracked)

| Artifact | Action |
|----------|--------|
| `fix_*.py`, `fix_*.ps1`, `fix_*.cjs` | Leave untracked — temporary repair scripts |
| `backup_*/` folders | Leave untracked — generated by batch repair scripts |
| `Therapy Documentation Feedback Agent Dev/` | Ask — may be a fresh export to track, or scaffolding |
| New agent folders (`POSTette Compliance Agent/`) | Ask — may need .gitignore or initial commit |
| `.cursorrules` | Depends on project convention — ask |
| `.kiro/skills/`, `.kiro/specs/`, `.kiro/hooks/` | Only commit if kiro is a project-standard tool |
| New topic files that are referenced by existing routers | These SHOULD be committed |

## Presenting the Report

When the worktree is too broad to commit blindly, present:

1. **Summary** — total files, insertions/deletions, agents touched
2. **Category breakdown** — steering, each agent, untracked
3. **Intentional vs noise** — which changes are real, which are CRLF re-export noise
4. **Recommendation** — commit grouping options (narrow one-agent commit vs multi-commit vs single blob)
5. **Risks** — line-ending noise mixing, untracked scripts, scope drift from branch name

## Scope Drift Detection

Check whether the branch name matches the actual changes:

- Branch `tda-format-fix-and-synthetic-tests` → changes should be about TDA format fixes
- If changes span 8+ agents but the branch implies one agent, flag scope drift
- Steering file rewrites may intentionally broaden scope — check with user

## YAML Export vs Real Edit Diff Inspection

When `pac copilot pull` or `manage-agent.bundle.js clone` is run, the output YAML differs from the committed state in predictable ways:

**Export-only changes (ignore for content purposes):**
- CRLF→LF line ending normalization
- Extra blank lines between every YAML node (pretty-print)
- Trailing whitespace removed
- Tab→space conversion
- Block scalar quoting style changed (`|-\n` vs `|-\r\n`)

**Mixed signals** — export may also add `variable: Topic.Answer` to `SearchAndSummarizeContent` nodes or reformat `additionalInstructions` indentation. These are still re-export artifacts, not intentional edits. Cross-reference against the live agent's current state before concluding content changed.

**Real edits** are structural additions/removals that change behavior, not formatting.
